# Engineering conventions
Python typed domain service functions; Django migrations committed, no manual production schema changes. Ruff formatting/lint, pytest/pytest-django; TypeScript strict, ESLint/Prettier, accessible reusable components. SQL through ORM unless justified and parameterized. UTC storage, Africa/Kampala display; money integer UGX; no float prices. IDs UUID, stable codes, separate public slugs. No arbitrary path traversal or external URL fetch from user input. No secrets or fixture data in production; .env.example placeholders only. Pin tested dependencies and lockfiles; deterministic clean installs in CI.

Branch per phase or cohesive change; proposed branch codex/phase-01-admin-foundation. Protected main, review required, no force push, no direct production deploy. Conventional commits encouraged. CI: lint/typecheck, migrations check, PostgreSQL integration, frontend build, browser tests, dependency/security scan, container build. Each phase supplies changed files, tests with counts, known failures, migration/rollback steps and evidence; mark PASS/PARTIAL/BLOCKED honestly. Never claim release based solely on mocked tests. Keep original archive checksum and baseline separately.
