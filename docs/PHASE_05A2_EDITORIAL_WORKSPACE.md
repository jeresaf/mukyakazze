# Phase 05A.2 — Tabbed editorial workspace (candidate)

Baseline: GitHub `7117291bf5efe201590f390dc0cc3b8546081d3a`. Frontend-only; no schema, API or permission changes. Eight sections: Summary, Events, Bugy's Picks, Night Grid, Cover, Features, Coming Up, Approval. Summary shows saved counts and revision, not a computed publication status. Existing event selection and settings drafts survive navigation between Summary, Events and Picks; use Save settings and Save selection and picks independently. Leaving these sections for a server-backed panel requires discarding or first saving pending edits. Cover, grid, features and teasers load on entry, retain optimistic revision checks and prompt before discarding changes. Approval acts on saved content only. Browser refresh, sign-out, sidebar and Back to issues are guarded for the active issue editor (other modules retain their existing behavior). Save-in-progress blocks issue navigation. The overview has compact spacing, quick actions before event activity, and a fixed brand region with independently scrolling desktop navigation. No new dependencies.

Qualification: rebuild and run existing Django check, migration dry-run, all 100 backend tests and hosted frontend build. Browser tests: `e2e/editorial-tabs.spec.ts` adds two fixture-based UI interaction cases using isolated authenticated staff login and intercepted read-only issue endpoints. These do not replace end-to-end persistence testing. Run all existing browser cases against a disposable development database and verify real issue settings, roster, cover, grid, feature, teaser, and approval saves independently; test narrow screens and stale versions.
