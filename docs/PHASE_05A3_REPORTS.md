# Phase 05A.3 — operational reporting candidate

Reports & analytics is restricted to event managers (Administrator and Editor); named staff activity requires account-management permission (Administrator). Existing backend permissions are enforced independently of navigation. Date filters refer to inclusive editorial dates (not activity timestamps); issue reports filter by week start. Unscheduled drafts are excluded. Cancelled occurrences are separate; category/venue/area and status totals cover active occurrences only. Review action counts and completed submit-to-verify durations include historical actions for that active cohort. Creator counts attribute recurring occurrences to the original event creator, not the person who entered every field. Current submission and assignment counts are not historical productivity metrics. No staff ranking. Paid disclosures count selected issue entries, not charges or revenue. Fee recording and payment reconciliation remain deferred. No database migrations or dependencies.

Requests bounded to 366 dates, 5000 occurrences and 20000 decision records; narrower filters required above these caps. Current issue readiness is recomputed via existing review logic and locks. Excel recalculates the saved report on download (not an immutable snapshot); all strings explicitly encoded as text, with invalid XML control characters removed. No private contacts, internal notes, verification evidence or approval reasons. Staff names only for administrators; UUID fallback when blank. Browser displays at most 30 groups per breakdown; Excel contains every group. Runtime and load qualification pending.
