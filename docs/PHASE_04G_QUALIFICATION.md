# Phase 04G — editorial readiness and independent approval (candidate)

Baseline: `241518c63f354e5e5db2ec766558af36f589b69d` (91 local backend tests and hosted CI reported passing). This batch adds a revision-bound readiness and approval API at `issues/<uuid>/review/` and a panel inside the issue workspace. No database migration is required: decisions are recorded as append-only audit events. The review endpoint, not the legacy issue status field, is authoritative for editorial readiness. The issue directory opens the review workspace rather than showing a potentially stale approval badge.

Proposed readiness policy: exactly seven distinct ranked picks with Why Go; active, verified, unchanged roster with valid catalogue/media links; title/byline/intro; cover name/subtitle, three complete cover lines and valid cover/headshot; at least one eligible collision-free Night Grid placement; feature title/subtitle/kicker and at least one tip; optional sponsor must have an active logo; teasers must follow the issue and have sources/active categories. Missing contact labels, suggested layout lengths, unknown prices and unverified teasers are warnings. Submit and approve require explicit warning acknowledgement; approval additionally requires confirming teaser sources. Teasers remain labelled unverified; approval does not change event verification.

Administrators and Editors can submit. Only an Administrator (existing manage_accounts permission) with editorial change permission who has never contributed to the issue and is not its latest submitter may approve/return it. This conservative rule also applies to superusers. A separate administrator account is necessary. The approval records the exact saved issue revision and a SHA-256 fingerprint of selected occurrences, prices, presentation, feature, teaser and related catalogue/media versions. The API recalculates current readiness under the existing transaction lock and category/media row locks. A changed fingerprint or failed blocker makes prior submission/approval stale, requiring resubmission; no changes are silently approved. Decision IDs prevent duplicate concurrent review actions. Edits are not frozen; review does not grant publication authority, create a public endpoint or persist a full immutable publication snapshot. Final render, release and financial fee handling remain deferred. Approval reviews the saved revision, not unsaved input in other panels.

Run `docker compose up --build -d`, `docker compose exec backend python manage.py check`, `docker compose exec backend python manage.py makemigrations --check --dry-run`, and `docker compose exec backend pytest -q -p no:cacheprovider`.
